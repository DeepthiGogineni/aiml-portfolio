Artifact 1 • Workshop 1.5

The Machine Learning Algorithm Map

A visual framework that sorts 15 machine learning algorithms by how they learn and by the kind of data they work on.

October 2026IWU AIML CourseVisual framework
About this artifact

Overview

Introduction

I made this artifact for Workshop 1.5 of the AIML course at Indiana Wesleyan University. A list of algorithm names does not help anyone choose between them. This map puts 15 well known algorithms side by side so a reader can see what each one is for, how it learns, and how it relates to the others.

Description

An infographic with four columns for the main application domains (Tabular Data, Computer Vision, Natural Language, Generative AI) and a band for tools that work across domains. Each card names the algorithm, shows whether it is supervised, unsupervised or self-supervised, explains how it works in one sentence, and gives a real use case. Small tags show where else an algorithm is used and which ones build on each other.

Objective

To classify key machine learning algorithms by learning style and application domain, and to show their similarities and differences clearly enough for a reader who is not a specialist.

Process

  1. Listed the algorithms named in the assignment and the two course videos, then added a few so every domain had at least three.
  2. Asked what kind of data each algorithm works on and placed it in a domain column.
  3. Asked how each one learns and gave it a supervised, unsupervised or self-supervised badge.
  4. Wrote a one sentence explanation and a real use case for each, in plain words.
  5. Added relationship tags and a quick decision guide, then reviewed every placement and moved the ones that did not fit cleanly.

Tools

  • HTML and CSS for the layout, so the text stays sharp and is easy to change.
  • Headless Chromium (Playwright) to export the layout as a high resolution PNG and PDF.
  • Course videos on AI, ML, DL and GenAI as the starting point for the categories.
  • An AI assistant (Claude) to help draft descriptions and check my wording. I reviewed and edited every entry.

Value proposition

It shows that I can organize a large technical topic into a clear structure and explain it to a mixed audience. That skill is needed when recommending an AI approach to a business team.

Unique value

Most algorithm charts sort by one idea. This one uses two, the data type and the learning style, and adds relationship tags and a decision guide. It also says openly where the categories blur, for example BERT and GPT.

Relevance

It connects to my Salesforce work: Einstein Prediction Builder uses tabular methods, Einstein Vision uses deep learning on images, and Agentforce is built on large language models like GPT. It also connects to my Workshop 1.4 project, where a Decision Tree sorted fruit photos with about 54 percent accuracy. This map shows why a CNN suits that data better.

Classification process

How I sorted the algorithms

Question 1: What data does it work on?

This sets the column. An algorithm goes where it is most often used, so Random Forest sits with tabular data and CNN sits with computer vision.

Question 2: How does it learn?

Supervised algorithms learn from labeled examples. Unsupervised algorithms look for patterns without labels. Self-supervised algorithms create their own labels from the data, such as hiding a word and guessing it.

Question 3: How are they related?

Some algorithms are built from others. Random Forest and Gradient Boosting grow out of the Decision Tree, YOLO builds on the CNN, and BERT, GPT and the Vision Transformer all use the Transformer. A nested diagram at the top of the map shows how AI, machine learning, deep learning and generative AI fit inside each other.

K-means and PCA

Both work on tables and on images, so a single column would mislead. I gave them a separate band with tags for both domains.

BERT and GPT

The assignment asks for supervised or unsupervised. These models train on text with no human labels, so supervised is wrong and unsupervised hides how they work. I added a self-supervised badge and noted that they are often fine tuned with labels later.

GPT and generative AI

GPT is both a language model and a generative one. I placed it under Natural Language, where most people use it, and tagged it Generative AI. A different reader could reasonably choose the other column.

What I left out

Support Vector Machines are named in the assignment, but I left them out to keep the map readable. They would go in the Tabular column in a later version.

Conclusion

Algorithms are tools for different jobs, and the useful question is not which one is best but which one fits the data and the labels you have. Tables usually call for tree based methods, images for convolutional networks, text for transformers, and new content for generative models. The map also shows that the categories overlap, and being open about those edge cases made the framework more honest and more useful.

Reflection

Artifact reflection

Before this assignment I knew most of these algorithms by name but mostly in isolation. I had used Decision Trees for the fruit workshop and heard of GPT and diffusion models every day, yet I had never put them next to each other. Building the map forced me to say exactly what each one is for. The idea that helped most was that two questions sort almost everything: what kind of data does it work on, and does it need labels to learn.

The hardest part was the algorithms that did not fit one box. K-means and PCA work on both tables and images, so I gave them their own band instead of choosing a column. BERT and GPT learn from text without human labels, but they are not unsupervised in the old sense, because the text supplies its own targets. The assignment asks for supervised or unsupervised, so I added a third label, self-supervised, and explained why. I also had to decide where GPT belongs, since it is both a language model and a generative one. I put it under Natural Language and tagged it Generative AI. I am still not fully certain that is the best answer, and a different reader could reasonably choose the other column.

The most useful connection was to my own Decision Tree project in Workshop 1.4. That tree sorted fruit photos with about 54% accuracy, and the map shows why: a tree is a tabular method and I fed it colour numbers pulled out of photos, while a CNN learns its own features from the pixels. Seeing Random Forest and Gradient Boosting drawn as improvements on the same tree also made it clear why they are the usual choice for tables.

In my work with Salesforce and Agentforce, the language model is what I meet most often, so it was good to see where it sits next to the rest of the field. I will keep this map in my portfolio, and the next step is to add a short code example for one algorithm in each column so that it shows what I can build and not only what I can classify.

Audience

This artifact is for classmates, instructors and hiring managers who know some machine learning terms but are not specialists. The explanations use plain words and each card has one example from everyday life or business.

Feedback and revisions

This artifact has not had a peer review yet. During the build I moved K-means and PCA into a cross domain band, added the self-supervised badge, added relationship tags, and fixed a legend that wrapped badly. I will update this section after the review.
