Introduction

This is my third portfolio artifact, for Workshop 3.4. In my Salesforce work I configure AI features such as Agentforce without seeing what it took to build the models behind them. This artifact looks at that hidden side: how a large language model (LLM) is trained and what it costs in data, computing power, energy and time.

Description

The artifact is one tall infographic. It follows a model through nine training stages in three phases, from collecting data to running the finished model. It then shows the four resource costs with real figures for GPT-3, Llama 2, Llama 3.1, DeepSeek-V3 and the outside estimates for GPT-4 and Gemini Ultra. A comparison table shows what is known and what is not. Claude is in the table too, with its figures marked as not disclosed.

Objective

To show clearly how an LLM is trained, what each resource contributes to cost, and how trustworthy each number is. A reader should be able to tell a reported figure from a derived one or an outside estimate.

Process

  1. Read the assigned resources, then the original papers and model cards for GPT-3, InstructGPT, Llama 2, Llama 3.1 and DeepSeek-V3.
  2. Listed every figure with its source and labelled it Reported (R), Derived by me (D), or Third-party estimate (E). Figures that nobody has published are marked Not disclosed.
  3. Put all inputs in one data file and calculated the derived values (energy, cost, growth ratios) by formula. 14 automatic checks recompute totals and compare them with the published numbers.
  4. Sorted the process into nine stages in three phases, then tagged each stage with the resources that drive it.
  5. Built the infographic in HTML and CSS, exported a 3600-pixel PNG and a PDF, and reviewed the rendered image for alignment, contrast and spelling.
  6. Wrote this page and the explanatory document from the same data file, so the numbers match everywhere.

Tools

  • Python to hold the data, calculate derived values and run the checks.
  • HTML, CSS and Playwright to build the infographic as live text and export it as PNG and PDF.
  • Primary sources for every figure: research papers, developer model cards and Stanford's AI Index.
  • An AI assistant (Claude) to help write the build scripts and first drafts. I checked each figure against its source and edited the wording.

Value Proposition

It shows that I can take a topic where the public numbers are messy, check them against the sources, and explain them for a mixed audience. Teams deciding whether to buy, fine-tune or build an AI model need someone who can say what a figure means and how much to trust it.

Unique Value

Artifact 1 sorted algorithms and Artifact 2 explained one algorithm family hands-on. This one is about the infrastructure and economics behind generative AI. It also treats evidence quality as part of the content: every number carries a tag, and the blanks for closed models such as Claude and GPT-4 are shown instead of filled with guesses.

Relevance

Salesforce customers ask whether to use a hosted model or train their own, and what each request costs. Understanding where training cost comes from (mostly pre-training, with a small compute share for alignment) helps me explain those trade-offs and ask better questions about energy use and vendor claims.

The nine stages

  1. Stage 1: Collect data. Gather text, code and books from the web, licensed sources and human writers. GPT-3 started from 45 TB of compressed Common Crawl text. Main resources: Data.
  2. Stage 2: Clean and filter. Remove duplicates, spam and low-quality or unsafe text so the model learns from good examples. GPT-3 kept about 1.3% of that crawl (570 GB). Main resources: Data; supporting: Compute.
  3. Stage 3: Tokenize. Cut text into tokens (word pieces) and turn them into numbers the network can process. GPT-3 trained on 300 billion tokens; Llama 3.1 405B on 15.6 trillion. Main resources: Data.
  4. Stage 4: Design and set up. Choose the Transformer size and the token budget, then build and test the GPU cluster. Llama 3.1 405B: 126 layers, up to 16,384 H100 GPUs. Main resources: Compute; supporting: Time.
  5. Stage 5: Pre-train. Predict the next token billions of times. This is the longest and most expensive stage. Llama 3.1 405B used 30.84 million H100 GPU-hours. Main resources: Compute, Energy, Time.
  6. Stage 6: Supervised fine-tuning. Teach the model to follow instructions using human-written example answers. InstructGPT SFT used 4.9 petaflop/s-days vs 3,640 for GPT-3 pre-training. Main resources: Data; supporting: Compute.
  7. Stage 7: Align with human feedback. People rank answers; a reward model then steers the model toward preferred behavior (RLHF). A 1.3B InstructGPT was preferred to the 175B GPT-3. Main resources: Data; supporting: Compute.
  8. Stage 8: Evaluate and red-team. Run benchmarks and adversarial safety tests, then fix problems before release. Teams repeat this with stages 6 and 7 until quality and safety targets are met. Main resources: Time; supporting: Data.
  9. Stage 9: Deploy and monitor. Serve the model to users and watch quality, cost and misuse. The cost repeats with every request. Unlike training, this cost never ends while the model is in use. Main resources: Compute, Energy.

Sorting Rules

  • Phase rule. Stages are grouped by what they produce: a clean dataset (Phase A), a trained and aligned model (Phase B), or a running service (Phase C).
  • Primary tag. A stage gets a primary resource tag when reducing that resource would shorten the stage or cut its cost the most.
  • Supporting tag. A stage gets a supporting tag when the resource is needed but is not the limit.
  • Evidence rule. Every number is sorted by who produced it: the developer (R), me from reported inputs (D), or an outside estimator (E). If nobody has published it, it is marked Not disclosed.

Decisions and Trade-offs

  • Nine stages instead of five. Five stages (data, train, tune, test, deploy) hide the biggest finding. Splitting pre-training from fine-tuning and human feedback shows that stage 5 took about 98% of the compute in OpenAI's InstructGPT study while the alignment stages took 1.8%.
  • Four resource categories, not five. The assignment names data, compute, energy and time. I tested adding People and Money. People's work (writing examples, ranking answers) is a cost of creating data, so it sits under Data. Money is not a separate resource but the common unit that combines the other four, so it gets its own section in dollars.
  • GPU-hours under Time, FLOPs under Compute. FLOPs measure the work a model needs. GPU-hours measure how long hardware is busy doing it, which depends on the chip. Two models with equal FLOPs can have different GPU-hours, so GPU-hours are the bridge to time, energy and cost.
  • Fine-tuning and RLHF tagged Data first. Their compute is small (1.8% of the total in the InstructGPT study). What limits them is collecting human-written and human-ranked examples, so Data is the main driver and Compute is supporting.
  • Deployment included. The assignment asks for the process through deployment. It also shows a cost that training figures leave out: serving the model repeats with every request.
  • A second classification for evidence. Sorting each number as Reported, Derived, Estimate or Not disclosed lets readers compare models without treating an outside guess like a developer's own figure.

Corrections I Made While Building It

  • I first tagged GPT-3's energy, elapsed time and GPU count as reported. Reading Patterson et al. (2021) showed they are the researchers' estimates built from an NVIDIA press release and performance data from OpenAI, so I changed them to Estimate and striped the bars.
  • Llama 3.1's GPU-hours and emissions are in Meta's model card, not in the Llama 3 paper. I cite both for what each one contains.
  • I could not confirm earlier-year training costs from the AI Index (such as the original Transformer) in the sources I could read, so I left them out instead of quoting them from memory.
Reflection

Artifact Reflection

Lessons Learned

What changed in my thinking. I started with the idea that training an LLM is mostly a very large pile of GPUs. The sources showed a more varied picture. Data work matters just as much: GPT-3's team kept about 1.3% of the web crawl it started with. Human feedback uses under 2% of the compute, yet people preferred the 1.3-billion-parameter InstructGPT to the 175-billion-parameter GPT-3. The result that surprised me most was how little compute the step that makes a model useful actually needs.

The hardest part. Comparable numbers are hard to find. Meta and DeepSeek publish GPU-hours; OpenAI, Anthropic and Google publish almost nothing about their newest models. I had to decide what to do with the gaps. Filling them with rumors would make the graphic look complete and be wrong, so I show Not disclosed and use evidence tags. I also caught my own mistake: I had labelled GPT-3's energy figure as reported when it is an outside estimate. Fixing it made the graphic less tidy and more honest.

Strategies that worked. I put every input in one data file, calculated each derived value by formula, and ran 14 checks. One check compares emissions per megawatt-hour for Meta's two models: 0.42 for Llama 2 70B and 0.41 for Llama 3.1 405B. They agree closely, which suggests my GPU-hours-times-watts method matches how Meta counted. Because the graphic, page and document all read that file, a number cannot differ between them.

Connections to the course and beyond. Workshop 3.2 covered GPT-3's training data, which became stages 1 and 2 here. In Workshop 2.4 I counted 137 weights in a small network and watched a loss value fall; pre-training is the same loop with 405 billion parameters and 30.84 million GPU-hours. In Workshop 1.4 I trained a Decision Tree on a small dataset, a task that needs no special hardware. At work, these numbers help me explain why per-request cost and vendor transparency matter when choosing an AI service. Next I want to study the cost of running a model, which these training figures leave out.

Audience Customization

The graphic is written for classmates, instructors and business stakeholders who use AI tools but have not trained a model. Each stage has a plain-language description and one concrete example. Terms such as token, FLOP and GPU-hour are defined where they first matter. Colour is never the only signal: tags carry the resource name and an icon, and estimates are striped as well as outlined.

Limitations

  • Costs are compute-rental estimates for the final run only. Salaries, research, failed runs, data licensing, hardware purchase and serving are excluded.
  • Energy marked D multiplies reported GPU-hours by the GPU power the developer states. DeepSeek-V3 assumes 700 watts, the H100 rating, because DeepSeek did not publish a figure. Cooling and facility overhead are not added.
  • Models ran on different chips and years, so only orders of magnitude should be compared.
  • Claude, GPT-4 and Gemini Ultra are shown mostly as Not disclosed or outside estimates because the developers have not published training details.
